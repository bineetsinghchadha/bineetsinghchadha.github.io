LLMao Joins: joining tables when the values don't match

Project period: Fall 2025 · Team of three, NYU Big Data course

PythonNeo4jSentence-TransformersOpenAI API

A SQL join matches rows only when the join values are identical. Real tables rarely cooperate: one says USA, the other says United States of America. LLMao Joins is a join operator that finds those matches without sending every pair of values to a language model.

Background

There are two usual ways to join messy columns, and each fails in its own way.

  • Fuzzy matching compares spelling. It catches Microsft and Microsoft, but it has no idea that IBM and International Business Machines are the same company.
  • Asking an LLM handles meaning, but a join between two columns of 10,000 values has 100 million possible pairs. Checking them all is slow and expensive.

Our idea was a funnel. Cheap methods propose candidate pairs and score them. Pairs that are clearly matches or clearly not are decided on the spot. Only the uncertain middle goes to the LLM, under a fixed budget.

I built this with Aayush Shah and Kai Kang. My part was the front of the funnel: normalization, the similarity features, the value-matching module, and the step that sorts pairs into confidence bands.

How the pipeline works

  1. Normalize. Lowercase the text, strip accents and punctuation, drop a leading "the", collapse whitespace, and expand abbreviations. The abbreviation list can be supplied as a CSV, so a finance dataset and a geography dataset can each bring their own.
  2. Generate candidates. Three generators run and their results are merged:
    • a rule generator, which pairs values whose normalized forms are identical;
    • a string generator, which builds TF-IDF vectors over character 3-grams and keeps each value's 20 nearest neighbours above 0.6 cosine similarity;
    • an embedding generator, which encodes values with the MiniLM sentence-transformer and keeps the 10 nearest above 0.55.
  3. Extract features. Each candidate pair gets Levenshtein similarity, Jaro-Winkler, n-gram Jaccard and a MinHash estimate, alongside the scores from the generators.
  4. Score. The signals are combined into one weighted score between 0 and 1. A signal a pair doesn't have is left out of the average instead of counting as zero.
  5. Sort into bands. High scores are accepted, low scores are rejected, and the band in between is marked uncertain.
  6. Ask the LLM about the uncertain band. Each uncertain pair becomes one strict yes-or-no question to gpt-4o-mini at temperature 0. The number of questions is capped, and the run logs calls, tokens and estimated cost.
  7. Build the alias graph. Every value becomes a node in Neo4j and every scored pair an edge. We export the accepted edges and run weighted label propagation to find clusters of values that mean the same thing.
  8. Join on cluster id. Rows from the two tables join when their values fall in the same cluster.

Why a graph

Pairwise matching treats every pair on its own. A graph adds two things.

  • Transitive matches. If U.S. matches USA and USA matches United States of America, all three land in one cluster even though the first and last were never compared directly.
  • Memory. The graph persists between runs. A match the LLM confirmed once does not have to be paid for again on the next dataset.

It also makes the result explainable. For any joined row you can show the path of edges, and the signals behind each edge, that connected the two values.

Evaluation

We compared against Auto-FuzzyJoin on its own benchmark datasets, measuring precision, recall and F1 along with running time and LLM cost per run. The benchmark runner in the repository reproduces the comparison.

What I would change

  • Measure candidate recall directly. A true match that the generators miss can never be recovered later, so recall at the candidate stage deserves its own number.
  • Try BM25 over character n-grams, fused with the embedding ranks. It is a cheap first stage that tends to catch rare tokens such as codes and proper nouns.
  • Learn the weights. The scoring weights are set by hand. A small labelled sample would let us fit them.
